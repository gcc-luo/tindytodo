# 日记 Markdown 编辑器设计

## 范围与依据

本设计补充并覆盖 [`2026-10-20-diary-design.md`](./2026-10-20-diary-design.md) 中编辑器、正文存储和富文本格式相关约定。日记工作区、日期浏览、标签、搜索、回收站、SQLite/API 边界、自动保存状态及图片资源目录等其余产品规则继续沿用原规格。

当前远端主分支已有 Vue 3 + Tauri 日记工作区，编辑器使用 Tiptap 并将 `content_html` 存入 SQLite。本次把编辑体验调整为 VS Code 风格的 Markdown 编辑与实时预览，并保留现有日记数据和本地图片资源。

## 已确认的设计决策

- 采用 `md-editor-v3` Vue 3 组件，不自研 Markdown 编辑核心；库源码、样式和启用的扩展随应用打包，离线使用不依赖 CDN。
- 常规宽度下默认左右分栏：左侧 Markdown 源文，右侧同步渲染预览。提供只看编辑区和只看预览的切换入口。编辑区可用空间不足时自动使用单栏，并允许用户切换到预览。
- 日记正文以 Markdown 保存，`DiaryEntry` 与数据库新增 `content_md` 字段，作为新格式的唯一写入来源。标题、日期、标签仍保存在独立字段中。
- 支持 CommonMark 常用语法与 GFM 表格/删除线/任务列表：标题、段落、粗体、斜体、删除线、无序/有序/任务列表、引用、行内与围栏代码、链接、图片、表格及分隔线。表情作为 Unicode 文本插入。
- Markdown 工具栏保留可移植的语法操作。移除字体、字号、颜色、段落对齐、下划线和“清除富文本样式”等不能由标准 Markdown 稳定表达的控件；避免通过任意 HTML 扩展这些格式。
- 关闭原始 HTML 渲染。Markdown 预览只渲染启用的 Markdown 语法，不执行正文中的脚本或 HTML。
- 自动保存继续使用现有的串行防抖保存机制，正文改为保存 `content_md`。保存失败时保留当前 Markdown，显示错误并可重试；切换条目或工作区前继续执行已有的未保存刷新保护。

## 图片引用

- 沿用现有 Tauri 专用资源目录、文件选择、剪贴板粘贴、MIME 校验和孤立资源清理流程。
- 图片上传成功后在 Markdown 中插入标准图片语法，目标使用稳定应用资源标识（`diary-asset://<uuid>`），正文不写入绝对本地路径或 Base64 数据。
- `md-editor-v3` 的图片上传回调使用现有图片 API 保存资源；预览 URL 转换只允许解析有效 UUID，并通过现有日记资源接口读取图片。
- 更新引用扫描逻辑，从 Markdown 图片节点中取得有效资源 ID。删除或替换图片时，仍按原有待清理队列策略回收未引用资源。

## 已有 HTML 日记迁移

- SQLite 迁移新增可空的 `content_md` 列；旧 `content_html` 在转换完成后仍保留为迁移备份，不在此次升级时删除或覆盖。
- `content_md IS NULL` 表示该旧条目尚未迁移；新建日记直接将其初始化为 Markdown 字符串（空正文使用空字符串）。
- 应用加载旧条目时，使用随应用打包的 Turndown HTML-to-Markdown 转换器逐条转换，并添加图片自定义规则，将原 `data-asset-id` 转为 `diary-asset://<uuid>`。成功写入 Markdown 后才视为迁移完成。
- 转换应可重试且幂等。若转换或保存失败，保留旧 HTML、暂存转换结果并显示可理解的错误，不得清空日记或释放其图片资源。
- 浏览器开发模式中的旧 localStorage 条目采用相同的空值标记、转换规则与备份策略；图片二进制继续保留在 IndexedDB。
- 字体、字号、颜色、对齐和下划线等 HTML 专有样式没有标准 Markdown 等价物；迁移时保留文字和结构，转换 Markdown 可表达的标题、强调、列表、引用、链接和图片，不保留不可表达的视觉样式。

## 架构调整

- 将 `DiaryEditor.vue` 从 Tiptap 编辑器替换为 `md-editor-v3`，沿用现有标题、标签、保存状态、回收站动作和图片资源 API。
- `src/types.ts`、`src/api.ts`、Rust 数据模型及 SQLite 查询/更新改用 `content_md`；数据库升级保留 `content_html` 供旧条目转换与回滚。
- 浏览器开发模式的数据适配器升级条目结构，并将图片二进制继续保存在 IndexedDB。
- 搜索、日期树摘要和图片清理引用扫描改为处理 Markdown 正文；搜索和预览均不解析原始 HTML。
- 移除仅服务于 Tiptap 的日记图片节点/扩展和富文本 HTML 清理逻辑；保留仍被其他功能使用的共享代码。
- 保持 `DiaryWorkspace.vue`、日期/标签/回收站交互和待办工作区接口稳定。

## 验收标准

1. 可以直接编辑 Markdown 源文，并在足够宽的区域看到同步预览；单栏布局可切换编辑/预览。
2. 支持的 Markdown 格式在保存、重新打开和应用重启后保持一致；预览不执行原始 HTML。
3. 工具栏不显示字体、字号、颜色、对齐和下划线等不可移植格式，Markdown 源文可在常见 Markdown 编辑器中继续编辑。
4. 选择图片和粘贴图片后，正文使用稳定日记资源 ID；应用重启后预览仍能读取图片。
5. 更新后的搜索可匹配 Markdown 正文文本，删除/替换图片后未引用资源按原清理策略回收。
6. 旧 HTML 条目可以逐条迁移成 Markdown；迁移失败不丢正文、不删图，可重试；保留的旧 HTML 可作为回滚备份。
7. 自动保存状态、保存失败重试、切换条目防丢稿、标签和回收站行为继续符合原规格。
8. 860 px 最小窗口下编辑区仍可操作，布局不会强迫源文和预览各占一半而不可读。
9. 原生 Tauri 与浏览器开发模式都使用一致的 Markdown 数据结构；原有待办数据不受影响。

## 第一版排除项

云同步、Markdown 文件导入导出、版本历史、自定义 HTML/字体样式、协同编辑和额外 Markdown 方言。日记资源路径的导出打包可在未来的导出功能中另行设计。

## 主要依赖

- `md-editor-v3`：Vue 3 Markdown 源码编辑、实时预览、工具栏和图片上传回调。
- `turndown`：将已有日记的已清理 HTML 逐条转换为 Markdown，并为日记图片资源添加自定义转换规则。

依赖及 API 以项目使用的锁定版本为准；开发和运行时不加载外部 CDN 资源。
