# TinyTodo 日记功能设计

## 目标

在 TinyTodo 中加入本地优先的日记工作区，采用用户选择的 A 布局：月历、标签、按年月日浏览的日记树，以及右侧所见即所得编辑器。日记独立于待办任务存储，不改变现有任务功能和数据。

## 已确认的产品规则

- 日记作为与待办并列的工作区，通过应用侧栏中的工作区入口切换。
- 日记按本地日期归档；同一天可创建多篇日记，日期树展开后列出该日的全部条目，按创建时间从新到旧排列。
- 每篇日记有可选标题、正文和零个或多个自定义标签。
- 编辑器提供常用所见即所得排版：字体、字号、文字颜色、标题、粗体、斜体、下划线、删除线、段落对齐、有序/无序列表、引用、链接、表情、撤销/重做和图片。
- 图片可通过本地文件选择器插入，也可从剪贴板粘贴。第一版不要求拖拽插图。
- 日记自动保存。删除的日记进入回收站，可恢复或彻底删除；回收站中的条目保留其图片，彻底删除时清理这些图片。
- 日历标示有日记的日期及条目数量；搜索覆盖日记标题和正文；标签列表显示未删除日记的匹配数量。
- 视觉风格沿用 TinyTodo 当前安静的绿色系，并适配应用现有窗口尺寸（最小宽度 860 px）。

## 界面结构

### 工作区切换

在现有侧栏顶部增加“待办 / 日记”切换。待办工作区保留当前导航和交互。进入日记工作区后，侧栏显示日记专用导航，主区域显示日记编辑器。

### 日记侧栏

1. 搜索框：匹配标题和正文。
2. 月历：上月/下月切换；点击日期查看当天日记；当天日期有清晰选中状态，有日记的日期带数量或标记。
3. 标签：全部日记和用户创建的标签，显示活跃条目计数；可以新建、重命名和删除标签。
4. 日期树：按年份、月份、日期分层；可折叠；日期节点显示条目数，展开后展示标题和创建时间。空标题使用正文首句作为列表预览。
5. 回收站：单独筛选已删除条目，可逐条恢复或彻底删除。
6. 新建日记：使用当前选中日期；若当前没有选中日期则使用今天。

### 编辑区

顶部显示日期、条目创建/更新时间、自动保存状态和“新建日记”入口。编辑区包含标题输入框、可多选的标签及格式工具栏。正文宽度限制为适合长文阅读的版芯；工具栏在窄窗口下分组换行或横向滚动。

工具栏覆盖已确认的字体、颜色、段落和插图能力。图片插入后在正文中显示；本地路径不直接暴露给正文文本或导出 HTML，正文保存稳定的图片资源标识。

## 数据模型与持久化

### SQLite

以非破坏性迁移新增以下结构：

- `diary_entry`：`id`、`entry_date`（本地 `YYYY-MM-DD`）、`title`、`content_html`、`created_at`、`updated_at`、`deleted_at`。
- `diary_tag`：`id`、大小写不敏感唯一的 `name`、`created_at`。
- `diary_entry_tag`：`entry_id`、`tag_id` 的关联表，联合唯一并使用外键约束。
- `diary_asset`：`id`、可空的 `entry_id`、相对文件路径、MIME 类型、创建时间和 `pending_delete` 标记，用于维护图片资源归属及失败后的清理重试。

日期键使用本地日历日期，避免午夜 UTC 转换导致日记归入前/后一天。时间戳用于排序和自动保存状态。删除日记只设置 `deleted_at`；恢复时清空它。彻底删除时在事务中将资产标记为待清理并删除日记与标签关联；磁盘文件成功清理后删除资产元数据，失败时保留待清理记录并在下次启动时重试。

### 图片文件

原生应用将图片写入 Tauri 应用数据目录下专用的 `diary-assets` 子目录，数据库和正文只存资源 ID 与相对路径。用 Tauri 受限资源范围提供 WebView 图片读取能力，不开放任意本地文件访问。选图时复制到应用目录，剪贴板图片走同一保存流程。仅允许常见静态图片格式；读取/写入失败时不插入无效图片节点。

浏览器开发模式沿用项目现有的 localStorage 日记数据适配，并用 IndexedDB 保存图片二进制；两种模式通过相同的日记资源接口加载图片。

## 编辑与保存行为

- 标题、正文和标签变更后短暂防抖保存，并按条目串行化写入，避免快速连续输入造成旧内容覆盖新内容。
- 状态显示“正在保存 / 已保存 / 保存失败”。失败时保留编辑器中的当前内容，提供重试；切换条目或离开工作区前先刷新待保存内容，失败时阻止无提示丢稿。
- 新建条目立即创建空条目并聚焦标题；若标题为空，日期树以正文摘要作为名称。
- 图片先写入本地资源，再插入编辑器节点；正文保存后移除不再被当前条目引用的图片资源。文件删除失败时保留待清理记录，并在下次启动时重试。
- 搜索和日期/标签筛选只显示未删除条目；回收站单独显示已删除条目。
- 标签删除只解除其关联，不删除日记内容。

## 架构边界

- 新增独立日记工作区组件及编辑器组件，避免继续扩大 `App.vue` 的任务页面职责。
- 前端通过 `src/api.ts` 中的一组日记 API 访问数据；原生模式调用 Tauri 命令，浏览器预览模式调用本地适配器。
- Rust 数据库层负责 CRUD、标签关系、软删除/恢复/彻底删除和迁移；资源命令仅操作专用图片目录。
- 富文本编辑使用 Tiptap Vue 3。文字样式扩展提供字体、字号和颜色；图片上传/粘贴与资源保存由应用自己的处理器完成。

## 错误处理与安全

- 数据库操作失败时显示可理解的错误，并保留当前编辑内容。文件系统删除失败不回滚已完成的数据库删除，孤立文件清理会在下次启动时重试。
- 图片格式不支持、剪贴板没有图片或文件访问被拒绝时给出明确提示；失败不改变正文。
- 图片资源协议只开放日记图片目录。编辑器只持久化其支持的结构化节点和格式标记，不执行任意脚本 HTML。
- 日期树、日历和标签计数只根据有效的未删除条目更新；彻底删除图片时若文件已不存在，数据库仍可完成清理。
- 旧版数据库只新增表和索引，不改动、不迁移或删除现有待办数据。

## 验收标准

1. 可以在待办和日记工作区之间切换，现有任务操作保持可用。
2. 可以按月历选日期、按日期树展开日记，并在同一天新建多篇；关闭重开应用后仍按创建时间显示。
3. 可以创建、重命名、删除和筛选自定义标签；一篇日记可有多个标签，也可无标签。
4. 富文本格式保存并在重新打开后保持；标题允许为空。
5. 本地图片选择和剪贴板图片粘贴可插入日记；应用重启后图片仍显示。
6. 自动保存状态准确；模拟保存失败时内容不丢失，用户可重试。
7. 软删除、恢复和彻底删除正常；彻底删除时清除条目图片，恢复时图片完整。
8. 搜索标题/正文、日期筛选、标签筛选、日历标记和计数准确。
9. Tauri 数据库迁移及已有任务数据通过测试，浏览器开发模式具备可运行的持久化适配。
10. 在 860 px 最小窗口宽度下，日期导航、编辑工具栏和正文仍可操作。

## 测试计划

- Rust 单元测试：迁移兼容、条目 CRUD、同日多篇、标签关联、搜索查询、软删除/恢复/彻底删除及事务边界。
- TypeScript 单元测试：本地日期键、日历有日记标记、日期树排序、标签计数、搜索/筛选和自动保存状态转换。
- 前端构建和 Tauri 检查：类型检查、生产构建、Rust 检查及测试。
- 手动验证：选择本地图片、剪贴板粘贴、应用重启后图片加载、富文本持久化、保存失败重试、回收站恢复与彻底删除，以及最小窗口宽度。

## 不在第一版范围

云同步、多设备协作、拖放插图、语音转写、版本历史、PDF/Word 导出、模板和自动生成日记。
